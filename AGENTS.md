# AGENTS.md

Angular 22 standalone-component SPA ("Compliance Portal") generated by Infragistics App Builder / Ignite UI CLI. All business logic lives client-side; there is no backend.

## Commands
- `npm start` / `npm run build` — dev server / production build
- `npm test` — runs unit tests (`ng test --watch=false`)
- `npm run lint` — eslint (TS + HTML templates)

Set `-- https://` not relevant. Angular CLI is used directly via npm scripts.

## Testing (Vitest, NOT Karma)
- Tests use the **Vitest** runner via `@angular/build:unit-test` (`runner: vitest`), with `happy-dom` as the DOM environment. The README's mention of Karma is stale — ignore it.
- Focused run of one suite: `npx ng test --watch=false --include='src/app/master-view/master-view.component.spec.ts'`
- Spec files use `TestBed.configureTestingModule`; globals come from `vitest/globals` (types in `tsconfig.spec.json`).
- `ComplianceRepositoryService` talks to IndexedDB (a browser API), so specs must provide a fake/mock (see `master-view.component.spec.ts`). Avoid exercising the real service in unit tests.

## Architecture
- Standalone components throughout; no `NgModule`s. Root bootstrap via `bootstrapApplication` (`src/main.ts`), routing from `src/app/app.config.ts` + `app.routes.ts`.
- Almost all logic is in `src/app/master-view/master-view.component.ts`: single component handles both client and admin modes via a `mode` field. It contains validation, PDF report generation (hand-built PDF byte stream), and state transitions.
- Persistence is browser-local **IndexedDB** through `ComplianceRepositoryService` (`src/app/compliance-repository.service.ts`); no API server. IDs come from `crypto.randomUUID()`.
- Domain types + statuses (`NOT_APPROVED | PENDING | APPROVED`) in `src/app/compliance.models.ts`. Approval rule is `canApprove()`: base docs reviewed AND (follow-up forms disabled OR submitted).
- UI copy is in Spanish (es-BO locale used in reports); keep new user-facing strings in Spanish.

## Conventions & gotchas
- Templates/inline templates use SCSS (`inlineStyleLanguage: scss`); component style extension is `.scss`.
- Selector prefixes: component `app` (kebab-case), directive `app` (camelCase) — enforced by ESLint.
- `tsconfig.json` sets `strict`, `strictTemplates`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns` — respect these; the linter relaxes `no-explicit-any` and `prefer-inject`.
- Not a real git checkout yet in this dir — git is initialized at the parent home dir on branch `desarrollo` with no commits. `npm install` before first build/test if `node_modules` is missing.
